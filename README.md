# Tomato · frontend

React + TypeScript + Vite. Интерфейс для входа, личных задач, комнат, общего Pomodoro и истории.

## Запуск

Нужен Node.js **22.12+**. Из папки `frontend/`:

```sh
npm ci
npm run dev
```

Откройте **http://localhost:5173**. Первое открытие показывает обозначенный баннером демо-режим. В нём можно создавать и редактировать задачи, запускать 25-минутный Focus, ставить его на паузу, отменять и смотреть локальную историю. Примерные задачи и сессии не относятся к реальному аккаунту. Демо-данные сбрасываются при перезагрузке страницы.

Кнопка «Войти» открывает вход или регистрацию. После входа данные загружаются из backend. JWT сохраняется в `localStorage`; «Выйти» удаляет его и открывает демо-пространство. При истечении сессии приложение сообщает об этом и предлагает войти снова.

## Подключение backend

В другом терминале, из папки `backend/`:

```sh
# Предварительно настройте backend/.env согласно backend/.env.example.
docker compose up -d
npm run migration:run
npm run start:dev
```

По умолчанию Vite перенаправляет `/api/*` на `http://127.0.0.1:3000/*`, а `/socket.io` — на Socket.IO этого backend. Для локальной разработки менять CORS не нужно: браузер обращается к одному origin frontend.

Если backend работает на другом адресе, скопируйте `.env.example` в `.env.local` и укажите:

```dotenv
API_PROXY_TARGET=http://127.0.0.1:3000
```

После изменения переменных перезапустите Vite.

## Как пользоваться

1. Зарегистрируйтесь или войдите. Создайте комнату, даже если работаете в одиночку.
2. Добавьте задачу. Кнопка ▶ рядом с ней делает её активной (`in_progress`). Чтобы выбрать другую, сначала нажмите паузу у активной задачи или завершите её галочкой.
3. Запустите Focus. Управление общим таймером доступно владельцу комнаты. Участники видят состояние и работают над собственными задачами.
4. В окне комнаты скопируйте код приглашения. Другой пользователь может войти по этому коду. Владелец также может передать управление участнику.
5. После Focus автоматически начинается 5-минутный Break. Историю формирует backend, включая раннюю отмену и выход из комнаты. Изменение выбранной задачи во время сессии относится к следующему Focus.

На экране «Задачи» доступны поиск, фильтрация, редактирование, завершение и удаление. В «Истории» доступны фильтры по периоду (включая собственный диапазон дат), результату и комнате, статистика и страницы результатов. Последний день диапазона включается целиком по часовому поясу браузера. Недельный график всегда показывает последние 7 дней по всем комнатам; карточки статистики и таблица учитывают выбранные фильтры. Данные никогда не создаются от имени другого участника.

Таймер рассчитывается по серверному `endsAt` с поправкой часов по `serverTime`. После reconnect или возвращения на вкладку запрашивается новый `room:snapshot`. При отсутствии связи управление отключается. Для проверки изменения членства и владельца через другие клиенты выполняется периодическое HTTP-обновление.

## Сборка и проверки

```sh
npm run build
npm run typecheck
npm test
npm run preview
```

`npm test` проверяет расчёт таймера с поправкой часов, паузу и истечение срока, статистику и фильтры истории, HTTP-авторизацию, пустые ответы, сетевые ошибки и истёкшие токены. Также выполняется серверный рендер трёх экранов. Эти проверки не заменяют проверку интерфейса в браузере и соединения с работающим backend.

Готовая production-сборка находится в `dist/`.

## Развёртывание

При размещении frontend и backend под одним origin настройте прокси `/api` (без префикса при передаче backend) и `/socket.io` с поддержкой WebSocket. Для раздельных origin перед сборкой задайте:

```dotenv
VITE_API_URL=https://api.example.com
VITE_SOCKET_URL=https://api.example.com
```

В backend добавьте адрес frontend в `CORS_ORIGINS`. Все переменные с префиксом `VITE_` видны в браузере; секреты в них не размещаются.

Браузерный клиент Socket.IO 4.8.4 включён локально из установленного официального backend-пакета; происхождение и MIT-лицензия находятся в `src/vendor/`. Внешний CDN для соединения не используется. Шрифты системные: интерфейс не загружает внешние шрифты или графику.

## Pixel-art интерфейс

Общая навигация: `/#focus`, `/#tasks`, `/#history`.

- `src/App.tsx`, `src/styles.css` — навигация, адаптивная компоновка и единый пергаментный стиль.
- `src/components/Village.tsx`, `src/lib/village.ts` — деревня и четыре декоративных жителя с определёнными маршрутами и остановками. Они не изображают реальных участников комнаты; участники перечислены в окне комнаты.
- `src/components/Timer.tsx` — деревянный Pomodoro с пиксельными цифрами, серверным временем и прежними Socket.IO-командами.
- `src/components/TaskList.tsx`, `History.tsx`, `ActivityChart.tsx` — задачи, фильтры, история и общий недельный график.
- `src/components/Modal.tsx`, `AuthModal.tsx`, `RoomModal.tsx`, `TaskEditor.tsx`, `PixelAvatar.tsx`, `Icon.tsx` — общие окна, формы и графические элементы.
- `src/hooks/useWorkspace.ts`, `src/lib/types.ts`, `src/lib/utils.ts`, `src/lib/demo.ts` — получение названий комнат и поддержка фильтров истории.
- `public/art/`, `public/tomato.svg` — оригинальная пиксельная графика и значок. Карта и спрайты весят около 43 КБ, анимационная библиотека не нужна.

Кнопка «Деревня живёт» останавливает движение; настройка сохраняется в браузере. При `prefers-reduced-motion: reduce` движение и переходы отключены. На скрытой вкладке анимационный цикл останавливается.

Графика воспроизводится без сторонних зависимостей:

```sh
python3 scripts/build-art.py
```

Для фильтра комнат нужен обновлённый backend: миграция `HistoryRoomNames1794960000000` и `GET /history/rooms`. При старой версии API интерфейс явно сообщает, что фильтр недоступен. Название комнаты сохраняется при старте Focus и остаётся в истории после удаления комнаты. Дедлайны и приоритеты не входят в существующую модель задач; интерфейс показывает реальную дату создания.

### Проверено в ограниченной среде

Сборка, TypeScript и автоматические frontend/backend проверки выполняются без работающей БД. Запуск Vite на `127.0.0.1:5173` в среде агента запрещён (`EPERM`), Chrome не запускается; визуальные и интерактивные сценарии в браузере требуют локального запуска. Интеграционные тесты backend требуют доступного PostgreSQL и отдельной БД `*_test`; запуск здесь остановился на подключении к PostgreSQL, до выполнения тестов.

После локального запуска проверьте: регистрацию/вход, создание и приглашение в комнату двумя аккаунтами, передачу владельца и выход; CRUD задач и выбор активной; старт, паузу, продолжение, отмену и переход Focus → Break; появление сессии и фильтры истории; ширину 390 px, управление клавиатурой и reduced-motion.
